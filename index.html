TabFM-Auto: Self-Evolving Pipelines for Tabular Foundation Models

Taking the best of both worlds: pairing a language-model coding agent's domain reasoning with a frozen 400M-parameter TabFM backbone's zero-shot numerical prior reaches 2013.0 Elo (#1) across all 51 TabArena datasets and ranks #1 overall on MLE-Bench-Tabular.

Abstract

Tabular foundation models achieve strong zero-shot accuracy on structured data by pretraining on synthetic tables, yet their attention layers ignore the column names, task descriptions, and auxiliary files that carry dataset semantics. Meanwhile, self-evolving machine learning engineering (MLE) agents read dataset metadata and write feature code, yet training gradient-boosted trees or neural networks from scratch on each candidate iteration is noisy: stochastic training variance masks small feature gains and drives validation overfitting. We introduce TabFM-Auto, which takes the best of both worlds by pairing a frozen 400M-parameter tabular foundation model, TabFM, with a language-model coding agent that iteratively evolves the surrounding data pipeline. Guided by dataset metadata and 3-fold cross-validation feedback on the training set, TabFM-Auto refines data cleaning, domain and structural feature engineering, multi-view context selection, and post-processing while keeping TabFM's weights fixed. Across all 51 datasets of the TabArena benchmark, TabFM-Auto takes the #1 overall position at 2013.0 Elo (+227.7 Elo over plain TabFM and +344.6 Elo over 4-hour AutoGluon 1.5 (extreme)). The discovered Python pipelines also transfer without further search to other frozen tabular foundation models, boosting TabICLv2, TabPFN-3, and EXAONE-Tabular by +88.7 to +143.3 Elo. On the 8 tabular competitions of MLE-Bench, TabFM-Auto ranks first overall (1827 Elo, 86.7% pairwise win rate) ahead of 12 external MLE agents.

1. Introduction: Taking the Best of Both Worlds

Modern tabular machine learning has split into two paradigms whose strengths and blind spots are mirror images of one another: pretrained Tabular Foundation Models (TFMs) that perform zero-shot numerical inference in a single forward pass, and LLM-driven Machine Learning Engineering (MLE) agents that read dataset metadata and write custom modeling code.

World 1: Tabular Foundation Models have strong numerical priors but are blind to column semantics. Tabular Foundation Models such as TabPFN, TabICL, and TabFM pretrain a transformer on millions of synthetic datasets so that, at test time, they take a labeled training table (Xtrain, ytrain) as in-context examples and predict test labels ŷ = fθ*(Xtest ∣ Xtrain, ytrain) in a single forward pass without gradient updates. Because their pretrained weights θ* stay frozen, TFMs provide fast, deterministic numerical inference and already match or outperform tuned gradient-boosted decision trees (GBDTs) and multi-hour AutoGluon stacks out of the box (1785.3 vs. 1668.4 Elo on TabArena). However, their attention layers see only floating-point magnitudes and category indices: a TFM treats a column named systolic_bp, frequency, or ICD9_diagnosis identically to an anonymous column X_17. From raw numbers alone, a TFM cannot infer dimensionless aeroacoustic scaling laws from wind-tunnel headers, group clinical diagnosis codes by organ system, recognize when a value such as width = 0 encodes a missing measurement rather than zero physical width, or read auxiliary sensor waveforms and 3D molecular geometries. Prior wrapper presets (TabFM+) extend TabFM with generic pairwise feature crosses, singular value decomposition (SVD) projections, and multi-view ensembling, but these fixed, schema-agnostic operations still ignore what the columns represent.

World 2: LLM Coding Agents understand column semantics but suffer from noisy end-to-end training search. Pretrained on scientific text and source code, Large Language Models (LLMs) possess the exact domain knowledge that TFMs lack: they read column names, physical units, task descriptions, and file schemas, and can express domain hypotheses directly as executable Python transformations. Yet LLMs perform poorly as direct row-by-row tabular predictors because of context-length limits, coarse number tokenization, and poorly calibrated probabilities. Existing MLE agents (such as AIDE, R&D-Agent, and MLEvolve) instead use LLMs to iteratively rewrite end-to-end training scripts that fit tree ensembles or neural networks from scratch during search. However, searching over feature engineering, model families, and training hyperparameters at the same time is slow and noisy: stochastic training variance masks small, legitimate feature gains and drives validation overfitting. In our controlled ablation using the exact same agent harness, language model, sandbox, and 6-hour per-dataset budget, an unconstrained coding agent that trains and blends LightGBM, CatBoost, XGBoost, and PyTorch models reaches only 1468.8 Elo on TabArena — falling behind 4-hour AutoGluon 1.3 (1490.3 Elo) and trailing plain zero-shot TabFM by 316.5 Elo.

Taking the Best of Both Worlds with TabFM-Auto. We introduce TabFM-Auto, which combines an LLM coding agent's domain reasoning with a frozen TabFM model's numerical inference prior. Rather than rewriting training scripts to fit models from scratch, the agent iteratively evolves a modular 4-stage Python data pipeline — data cleaning (preprocess), feature engineering (engineer), context selection (sample), and post-processing (postprocess) — via 3-fold cross-validation on the training set while keeping TabFM strictly fixed. Because TabFM requires no gradient updates, every candidate pipeline is fast to evaluate and free of model-retraining noise: even a 0.2% cross-validation gain reflects a genuine improvement in how the table is represented. Once search finishes, we freeze the selected pipeline P* and evaluate it once on the official held-out test set.

2. Methodology: Closed-Loop Pipeline Evolution Around Frozen TabFM

Consider a tabular prediction task with a labeled training dataset Dtrain = (Xtrain, ytrain) of Ttrain rows and H columns, an unlabeled test dataset Xtest, and dataset metadata M containing column names, physical units, task descriptions, and auxiliary file schemas. A zero-shot tabular foundation model fθ* such as TabFM takes (Xtrain, ytrain) as in-context examples and predicts test labels ŷ = fθ*(Xtest ∣ Xtrain, ytrain) in a single forward pass with frozen weights θ*.

Optimization Objective. We partition Dtrain into 3 internal cross-validation folds without touching the held-out test split (Figure 2a). On each internal fold (Dsubtrain, Dval) and conditioned on metadata M, the coding agent searches over executable pipelines P = (Φclean, Φfeat, Sctx, Ψpost) ∈ P to maximize the mean 3-fold cross-validation metric Uval around the fixed weights θ*:

P* = arg maxP ∈ P  Uval( Ψpost( fθ*( X̃val ∣ Sctx(X̃subtrain, ỹsubtrain) ),  ysubtrain,  X̃val ),  yval ),    where  (X̃subtrain, ỹsubtrain, X̃val) = Φfeat(Φclean(Xsubtrain, ysubtrain, Xval)).
(1)

Throughout search, θ* stays fixed. Passing unlabeled inputs Xval (or Xtest at evaluation time) alongside the training split while withholding evaluation labels lets the pipeline compute both inductive transformations fitted on training rows and label-free transductive features (such as entity frequency and bipartite graph degrees across combined train and test inputs).

Modular Stages vs. Generic Wrapper Presets. Generic versions of all four stages already exist in TabFM+, which extends TabFM to normalize inputs and clip outliers (Φclean), append pairwise feature crosses and SVD projections (Φfeat), ensemble predictions over multiple views with a configurable context size (Sctx), and weight views by non-negative least squares (NNLS) before calibrating outputs (Ψpost). TABFM_KWARGS exposes these generic presets as constructor settings of fθ*. The coding agent can therefore cover standard numerical conditioning by setting dictionary flags and reserve the four Python functions for dataset-specific logic that generic presets cannot express — such as domain formulas, sentinel recoding, or minority-class context stratification. Separating TABFM_KWARGS from the four functions also allows us to transfer the evolved Python functions directly around other tabular foundation models (§6).

4. TabArena Evaluation Across 51 Datasets

Experimental Protocol. We evaluate TabFM-Auto across all 51 datasets of the TabArena benchmark (38 classification and 13 regression datasets, where each dataset uses 3-fold outer cross-validation repeated 3 or 10 times, yielding 9 or 30 official train/test splits). Running a separate agent search on every evaluation fold would be prohibitively costly in tokens and GPU hours. Instead, we run pipeline search once per dataset using 3-fold cross-validation on fold 0's training set (up to 96 candidate evaluations or 6 hours on one H100 GPU), withholding all test labels. We then freeze the selected pipeline P* and evaluate it once across the held-out test splits of all official folds k ∈ {0, …, S − 1}. Following the official TabArena protocol, each method is rated against the 66-method TabArena pool using Bradley–Terry Elo (anchored to default Random Forest = 1000), dataset Wins, oracle Improvability (1 − errbest / errmethod), and Geometric Mean Test Error (G-Mean).

Main Results. Across all 51 datasets (Figure 1 and Table 1), TabFM-Auto takes the #1 overall position at 2013.0 Elo, improving over plain TabFM (1785.3 Elo) by +227.7 Elo and outperforming 4-hour AutoGluon 1.5 (extreme) ensembles (1668.4 Elo) by +344.6 Elo. On the 38 classification datasets, TabFM-Auto raises TabFM by +197.6 Elo to 1966.3 Elo. On the 13 regression datasets, TabFM-Auto leaps by +467.0 Elo to 2512.9 Elo, improving over plain TabFM on all 13 datasets and driving oracle improvability down to 0.00%. Regression gains are particularly large because expressing physical ratios in engineer() and linearizing skewed targets in preprocess() lets TabFM smoothly interpolate continuous functions that axis-aligned tree splits approximate only coarsely.

5. What Do Evolved Pipelines Learn? Taxonomy & Search Dynamics

To understand the algorithmic strategies discovered during search, we analyze the final evolved pipelines across all 51 TabArena datasets and group them into three categories (Table 2): (I) Domain-Knowledge Features, (II) Statistical & Structural Feature Engineering, and (III) Context Selection & Output Calibration.

The evolved pipelines modify the feature table in 95.1% of runs, pairing feature engineering (Φfeat) with missing-value cleaning and reversible target transforms (Φclean) on regression, and with minority-class context selection (Sctx) and prior calibration (Ψpost) on multiclass classification. On the 17 datasets whose column names or task descriptions identify physical, clinical, or economic quantities (Category I), the agent writes domain formulas directly from the schema — reducing official test error across all folds by 7.3% to 8.2%. That is nearly three times the 2.3% to 3.0% error reduction on datasets with anonymized or generic schemas (Category II), where the agent relies on statistical transforms, frequency encodings, and bipartite graph degree features. Category I datasets account for 6 of the 10 largest test error reductions across TabArena.

def engineer(X_tr, y_tr, X_te):
    for df in (X_tr, X_te):
        f, u = df["frequency"], df["free-stream-velocity"]
        c, d = df["chord-length"], df["suction-side-thickness"]
        a = df["attack-angle"]
        df["log_st_d"] = np.log(f * d / u)  # Strouhal St = f*d*/U
        df["st_h"] = f * c * np.sin(np.radians(a)) / u
        df["helmholtz"], df["d_over_c"] = f * c / 343.0, d / c
    return X_tr, X_te

Aeroacoustic Scaling & Operating-Point Interpolation. From the five NASA wind-tunnel column headers, the pipeline constructs dimensionless aeroacoustic groups: the displacement-thickness Strouhal number St = fδ*/U∞, frontal Strouhal projection, Helmholtz acoustic compactness He = fc/a0, and thickness-to-chord ratio.

In addition, its helper functions _brackets() and _ecdf_grid() identify the two brackets of the (c, U∞, α) wind-tunnel grid surrounding each query point so TabFM can smoothly interpolate sound pressure levels across frequency sweeps.

def engineer(X_tr, y_tr, X_te):
    cols = [c for c in X_tr.columns if c != "row_id"]
    all_df = pd.concat([X_tr[cols], X_te[cols]], axis=0)
    for df in (X_tr, X_te):
        for c in cols:  # 1. Marginal entity frequencies
            df[f"{c}_cnt"] = df[c].map(all_df[c].value_counts())
        for c1, c2 in PAIRS:  # 2. Pairwise co-occurrences
            vc = all_df.groupby([c1, c2]).size()
            df[f"{c1}_{c2}_cnt"] = df.set_index([c1, c2]).index.map(vc)
        for s, t, nm in GROUP_MAPS:  # 3. Bipartite nunique degrees
            df[f"{s}_{nm}"] = df[s].map(all_df.groupby(s)[t].nunique())
    return X_tr, X_te

Turning Opaque Integer IDs into Bipartite Graph Topology. Raw columns are arbitrary integer IDs (RESOURCE, MGR_ID, ROLE_DEPTNAME) whose numerical magnitudes carry zero meaning to a TFM.

Without touching evaluation labels, engineer() pools unlabeled train and test inputs to compute marginal entity frequencies, pairwise role–resource co-occurrence counts, and bipartite cardinalities (e.g., how many distinct resources a manager oversees), paired with smoothed out-of-fold empirical Bayes target rates.

def postprocess(pred, y_tr, X_te):
    p, cols = pred.to_numpy(), pred.columns
    pi = y_tr.value_counts(normalize=True).reindex(cols).values
    z = np.log(p) + np.log(pi / p.mean(0))
    q = np.exp(z - z.max(1, keepdims=True))
    return pd.DataFrame(q / q.sum(1, keepdims=True), columns=cols)

Minority-Class Context Ensembling & Log-Odds Calibration. On imbalanced multiclass tables, rare classes (such as Suspicious) receive too few in-context examples and under-calibrated posterior probabilities.

sample() pairs the natural training draw with an oversampled minority-class view, while postprocess() shifts log-odds so mean predicted probabilities match the empirical training class prior π.

Validation-to-Test Generalization Across Search Progress. A natural question for any iterative search method is whether optimizing 3-fold cross-validation on fold 0's training set overfits the validation split. To test this directly, we evaluate 15 intermediate pipeline checkpoints per dataset — taken at fixed fractions of the search budget from 0% (identity baseline P0) to 100% (final pipeline P*) — on the official held-out test sets across all folds (Figure 3). Cross-validation gains on fold 0's training set (Figure 3a) translate monotonically into official test error reductions across all folds (Figure 3b) and higher TabArena Elo ratings (Figure 3c). Notably, TabFM-Auto surpasses TabFM+ (1856 Elo) within the first 2.5% of the search budget (roughly 3 candidate evaluations) and continues climbing to full budget without validation-to-test degradation.

(2) Are the evolved pipelines overfitted to TabFM's specific weights, or do they capture intrinsic dataset structure that transfers to other frozen tabular foundation models?

7. Multi-File Autonomous Engineering on MLE-Bench-Tabular

We further evaluate TabFM-Auto on MLE-Bench-Tabular, the 8 tabular Kaggle competitions of MLE-Bench, comparing against 12 external autonomous MLE agents (including CAIR MARS+, CAIR MARS, MLEvolve, Famou-Agent 2.0, PiEvolve, ML-Master 2.0, AIBuildAI, Thesis, CAIR MLE-STAR-Pro, R&D-Agent, AIDE, InternAgent, and AIRA-Dojo) that search over both feature engineering and custom model training (GBDTs, deep neural networks, and multi-stage ensembles).

In several competitions — such as predict-volcanic-eruptions-ingv-oe and smartphone-decimeter-2022 — the main CSV contains only recording IDs while the predictive signal lives in thousands of auxiliary sensor waveforms, GNSS satellite logs, or 3D molecular geometry files. Plain TabFM cannot read these auxiliary files directly. Within engineer(), TabFM-Auto writes domain-specific signal-processing and geometric parsers (FFT spectral energy bands, STA/LTA seismic trigger ratios, Ewald-like reciprocal lattice unit-cell volumes, Karplus dihedral angles, and weighted least-squares GNSS positioning with Rauch–Tung–Striebel Kalman smoothing) and joins the extracted features into a clean tabular representation for TabFM.

8. Discussion, Limitations & Citation

Summary. We showed how a language-model coding agent can evolve the data pipeline around a frozen tabular foundation model, combining language-model domain reasoning with fast forward-pass tabular inference to supply the semantics missing from synthetic pretraining. Across all 51 TabArena datasets, TabFM-Auto reaches 2013.0 Elo (#1 overall, +227.7 over plain TabFM), transfers zero-shot to other frozen tabular foundation models (+88.7 to +143.3 Elo), and ranks #1 overall on MLE-Bench-Tabular ahead of end-to-end MLE agents that train trees and neural networks from scratch.

Limitations and Future Directions. Two limitations suggest directions for future work. First, gains are smaller on anonymized tables (Category II, 2.3%–3.0% error reduction) than on tables with descriptive column names (Category I, 7.3%–8.2% error reduction), where the agent can exploit domain laws directly. Second, iterative pipeline search requires repeated validation evaluations on each dataset. Because the discovered pipelines are short, readable Python programs (median 89 lines), operations collected across datasets could form a reusable library that warm-starts search on new tables with far fewer evaluations, or be distilled into synthetic pretraining generators to build schema-aware tabular foundation models.
